==== *Core Concepts*

===== Actions, Events, and State Transitions

[.changed]#`TimeSlotCatalog` represents the current set of published slots and their states. `AppointmentBook` represents appointment records and their states. These are related but distinct: publishing or releasing a slot changes the slot catalog, while creating or confirming an appointment changes the appointment book. Many actions update both stores simultaneously.#


====== Slot Published

[.added]#*Type:* Event#
- *Definition:* [.changed]#A new time slot has been made available for booking.#
- *Trigger:* Completion of the Publish Slot action.
- *Observable Result:* A TimeSlot enters the `Available` state and becomes visible for booking.

- *Reference to sketch:* Providers define working hours; Jose cannot see other sites’ calendars to compare newly published slots.

----
publishSlot(
  slotCatalog: TimeSlotCatalog,
  provider: Provider,
  slotDraft: TimeSlotDraft
): Result (TimeSlotCatalog, TimeSlotId) Error
----

[.changed]#A successful publication returns an updated slot catalog together with the created slot identifier, because the operation conceptually creates a new visible slot.#

====== Publish Slot

[.added]#*Type:* Action#
- *Actor:* Provider or scheduling system
- *Definition:* [.changed]#A provider or system creates a new TimeSlot within a schedule and makes it available for booking.#
- *Resulting Event:* Slot Published
- *Resulting State:* TimeSlot becomes `Available`

====== Request Appointment

[.added]#*Type:* Action#
- *Actor:* Patient
- *Definition:* A patient selects an available TimeSlot and submits a booking request.
- *Trigger:* User submits booking request.
- *Resulting Event:* Appointment Requested
- *Resulting State:* Appointment enters `Requested` or `PendingApproval` depending on prerequisites.

- *Reference to sketch:* Carmen redialed 23 times starting 5 Feb 2026 at 8:02 a.m. to request a slot.

----
requestAppointment(
  slotCatalog: TimeSlotCatalog,
  appointmentBook: AppointmentBook,
  patient: Patient,
  slotId: TimeSlotId,
  consultationType: ConsultationType
): Result (TimeSlotCatalog, AppointmentBook, AppointmentId) Error
----

[.changed]#A successful request updates both stores: the appointment book gains a new request record, and the targeted slot transitions from `Available` to `Held` to prevent concurrent booking.#


====== Appointment Requested

[.added]#*Type:* Event#
- *Definition:* The system has recorded a booking request for a specific TimeSlot.
- *Trigger:* Completion of Request Appointment action.
- *Observable Result:* A pending appointment record exists and enters downstream processing (confirmation, waitlist, or rejection).

- *Reference to sketch:*
  * Carmen redialed 23 times starting 5 Feb 2026 at 8:02 a.m. to request a slot.

====== Confirm Appointment

[.added]#*Type:* Action#
- *Actor:* Clinic system or staff
- *Definition:* Validation of a pending appointment against constraints (availability, authorization, referral rules).
- *Resulting Event:* Appointment Confirmed
- *Resulting State:* Appointment becomes `Confirmed`

----
confirmAppointment(
  slotCatalog: TimeSlotCatalog,
  appointmentBook: AppointmentBook,
  appointmentId: AppointmentId
): Result (TimeSlotCatalog, AppointmentBook, AppointmentId) Error
----

[.changed]#A successful confirmation transitions the appointment to `Confirmed` and the associated slot to `Reserved`, making the booking final.#

====== Appointment Confirmed

[.added]#*Type:* Event#
- *Definition:* A pending appointment has been successfully validated and scheduled.
- *Trigger:* Completion of Confirm Appointment action.
- *Observable Result:* Appointment transitions to `Confirmed`; reminders and downstream workflows may be scheduled.

====== Cancel Appointment

[.added]#*Type:* Action#
- *Actor:* Patient or clinic staff
- *Definition:* Removal of an existing appointment from the schedule.
- *Resulting Event:* Appointment Cancelled
- *Resulting State:* Associated TimeSlot becomes `Available`

- *Reference to sketch:* Laura flips through a notebook and spreadsheet to reassign cancellations.

----
cancelAppointment(
  slotCatalog: TimeSlotCatalog,
  appointmentBook: AppointmentBook,
  appointmentId: AppointmentId
): Result (TimeSlotCatalog, AppointmentBook) Error
----

[.changed]#Cancellation returns updated stores because the appointment state changes and the slot is released back to `Available` for future scheduling.#


====== Appointment Cancelled

[.added]#*Type:* Event#
- *Definition:* An appointment has been removed from the schedule.
- *Trigger:* Completion of Cancel Appointment action.
- *Observable Result:* TimeSlot transitions to `Available`; waitlist reassignment may be triggered.

====== Join Waitlist

[.added]#*Type:* Action#
- *Actor:* Patient
- *Definition:* A patient registers interest in future availability when no slots are available.
- *Resulting Event:* Patient Added to Waitlist

----
joinWaitlist(

  patient: Patient,
  requestedType: ConsultationType

[.changed]#The result returns an updated waitlist value, reflecting the addition of a new entry rather than mutating the original structure in place.#


====== Patient Added to Waitlist

====== Slot Expiration Check

[.added]#*Type:* Action#
- *Actor:* System scheduler
- *Definition:* Periodic evaluation of held TimeSlots.
- *Resulting Event:* Slot Expired (if conditions are met)

====== Slot Expired

[.added]#*Type:* Event#
- *Definition:* A held TimeSlot has been released due to expiration of its hold window.
- *Trigger:* Completion of Slot Expiration Check.
- *Observable Result:* TimeSlot transitions to `Expired` and is no longer reservable.

====== Waitlist Reassignment

[.added]#*Type:* Action#
- *Actor:* System
- *Definition:* Assignment of an available slot to a waitlisted patient.
- *Resulting Event:* Waitlisted Patient Assigned

----
selectWaitlistCandidate(
  waitlist: Waitlist,
  slot: TimeSlot
): Option Patient
----

[.changed]#This function is a pure selection mechanism that determines the most appropriate patient for a given slot based on ordering rules. It does not modify system state and is typically used internally by reassignment logic.#

====== Waitlisted Patient Assigned

[.added]#*Type:* Event#
- *Definition:* A TimeSlot has been assigned to a patient from the waitlist.
- *Trigger:* Completion of Waitlist Reassignment action.
- *Observable Result:* Appointment is created and TimeSlot becomes `Reserved`

====== Reschedule Appointment

[.added]#*Type:* Action#
- *Actor:* Patient or clinic staff
- *Definition:* Changing an existing appointment by replacing its current TimeSlot with a new available TimeSlot.
- *Resulting Event:* Appointment Rescheduled
- *Resulting State:* Original TimeSlot becomes `Available`, new TimeSlot becomes `Held` or `Reserved` depending on confirmation stage.

----
rescheduleAppointment(
  slotCatalog: TimeSlotCatalog,
  appointmentBook: AppointmentBook,
  appointmentId: AppointmentId,
  newSlotId: TimeSlotId
): Result (TimeSlotCatalog, AppointmentBook) Error
----

[.changed]#Rescheduling is modeled as a composite operation: it releases the original slot and assigns a new one, ensuring both the appointment and slot states remain consistent across stores.#

====== Reassign Slot

[.added]#*Type:* Action#
- *Actor:* System
- *Definition:* Automatically assigns an available TimeSlot to a suitable patient from the waitlist when eligibility rules allow.
- *Resulting Event:* Waitlisted Patient Assigned
- *Resulting State:* TimeSlot becomes `Reserved`, Appointment is created or updated.

----
reassignSlot(
  waitlist: Waitlist,
  slotCatalog: TimeSlotCatalog,
  appointmentBook: AppointmentBook,
  slotId: TimeSlotId
): Result (Waitlist, TimeSlotCatalog, AppointmentBook, Option AppointmentId) Error
----

[.changed]#This operation combines selection and assignment: it may invoke `selectWaitlistCandidate`, and if a candidate exists, it creates a new appointment and updates both the slot catalog and appointment book consistently.#

====== Authorize Action

[.added]#*Type:* Action#
- *Actor:* Policy engine / system
- *Definition:* Evaluates whether a requested operation is permitted under system rules and constraints.
- *Resulting Event:* Authorization Granted or Authorization Denied
- *Resulting State:* No direct domain mutation; the action only controls whether execution continues.

----
authorizeAction(
  policy: Policy,
  subject: Entity,
  attemptedAction: Action
): Result Unit Error
----

[.changed]#`Unit` is used because successful authorization does not produce new domain data; it only permits or blocks execution of the requested action.#
