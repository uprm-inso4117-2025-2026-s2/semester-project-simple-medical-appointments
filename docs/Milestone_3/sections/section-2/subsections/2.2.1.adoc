=== *Requirements*


==== *User Stories, Epics, Features*

[NOTE]
This subsection defines the scope model (epics, features, user stories) from a user-value perspective.

[discrete]
==== Abbreviations and ID Conventions:

[cols="1,3",options="header,autowidth"]
|===
|Abbrev. |Meaning
|US |User Story: a user-centered need framed as intent and value.
|E |Epic: a high-level goal that groups related features and stories.
|F |Feature: a concrete capability that realizes part of an epic.
|ReqRef |Requirement Reference: the requirement ID(s) a story or feature maps to.
|REQ |Requirement: a functional or non-functional specification with a stable ID.
|===

[discrete]
==== Identifier Formats:

[cols="1,2,3,2",options="header,autowidth"]
|===
|Type |Format |Components |Example
|User Story ID:
|`US.AREA.NN`
|`AREA` = functional area (`AUTH`, `PROF`, `AVAIL`, `BOOK`, `SCHED`, `NOTIF`, `ADMIN`)
|`US.BOOK.01`
|Epic ID:
|`E#` or “Epic E#: Title”
|`#` = epic number
|`E1`
|Feature ID:
|`F#.N`
|`#` = epic number; `N` = feature sequence
|`F1.1`
|Requirement ID:
|`REQ-AREA-TYPE-NN`
|`TYPE` = `F` (Functional) or `NF` (Non-functional)
|`REQ-BOOK-F-01`
|===

[discrete]
===== *_Epic E1: Identity and Scheduling Profiles_*

*Goal:* [.changed]#Ensure that patients, providers, and staff can be recognized and represented consistently for scheduling actions.#

*Features (F1):*

* F1.1 Account registration and login
* F1.2 Patient profile management
* F1.3 Provider profile management
* F1.4 Role-based access control

[discrete]
===== _US.AUTH.01: Be recognized securely | ReqRef: <<REQ-AUTH-F-01>>_

_"As a patient, provider, or staff member, I want the system to recognize me securely so that scheduling actions and visibility rules are tied to the correct identity."_

[discrete]
===== *_Epic E2: Availability Publication and Search_*

*Goal:* [.changed]#Make provider availability visible as explicit time slots that can be searched and managed consistently.#

*Features (F2):*

* F2.1 Publish weekly or ad-hoc availability
* F2.2 Reject overlapping slots
* F2.3 Search by specialty, location, and supported filters

[discrete]
===== _US.AVAIL.01: Publish my availability | ReqRef: <<REQ-AVAIL-F-01>>_

_"As a provider, I want to publish availability in a structured form so that patients and staff can see the same slot state."_

[discrete]
===== *_Epic E3: Appointment Request, Confirmation, and Reassignment_*

*Goal:* [.changed]#Coordinate appointment requests, prerequisites, cancellation, rescheduling, and waitlists without ambiguous slot state.#

*Features (F3):*

* F3.1 Request an appointment
* F3.2 Represent `Requested`, `PendingApproval`, and `Confirmed`
* F3.3 Cancel or reschedule a future appointment
* F3.4 Prevent double booking
* F3.5 Join and process waitlists

[discrete]
===== _US.BOOK.01: Request an appointment | ReqRef: <<REQ-BOOK-F-01>>, <<REQ-CONFIRM-F-01>>_

_"As a patient, I want to request a suitable appointment slot so that the system can either confirm it or tell me what prerequisite still blocks it."_

[discrete]
===== _US.BOOK.02: Cancel or reschedule | ReqRef: <<REQ-BOOK-F-02>>_

_"As a patient, I want to cancel or reschedule an eligible future appointment so that the released time can be reused and my schedule stays accurate."_

[discrete]
===== _US.WAIT.01: Join a waitlist | ReqRef: <<REQ-WAIT-F-01>>_

_"As a patient, I want to register interest in a future opening when no current slot fits my needs."_

[discrete]
===== *_Epic E4: Notifications and Reminders_*

*Goal:* [.changed]#Keep patients and staff informed about state changes that affect attendance and coordination.#

*Features (F4):*

* F4.1 Booking or status-change notifications
* F4.2 Reminder notifications

[discrete]
===== _US.NOTIF.01: Receive appointment updates | ReqRef: <<REQ-NOTIF-F-01>>, <<REQ-NOTIF-F-02>>_

_"As a patient, I want timely updates about my appointment state so that I know whether to attend, wait, or take another action."_
