===== Backend Application Factory

[.changed]#The backend is initialized through a Flask application factory (`backend/app/__init__.py`) that centralizes configuration, CORS, database initialization, Supabase initialization, and blueprint registration.#

[source,python]
----
def create_app(testing: bool = False):
    app = Flask(__name__)
    app.config.from_object(Config)
    if testing:
        app.config['TESTING'] = True
    CORS(app)
    db.init_app(app)
    init_supabase(app)
    register_routes(app)
    with app.app_context():
        db.create_all()
    return app
----

[.changed]#This setup keeps startup responsibilities explicit and supports test-mode behavior through the `testing` flag.#

===== Supabase Integration and Configuration

[.changed]#Supabase client setup is implemented in `backend/app/supabase.py` and wired into the factory. Runtime values come from `backend/app/config.py`, where URL/key/JWT settings are loaded from environment variables.#

[source,python]
----
def init_supabase(app):
    if app.config.get("TESTING"):
        app.supabase = None
        return None
    url = app.config.get('SUPABASE_URL')
    key = app.config.get('SUPABASE_KEY')
    supabase = create_client(url, key)
    app.supabase = supabase
    return supabase
----

[.changed]#This keeps external service wiring in one place and provides a clear test-mode branch.#

===== Authentication Middleware

[.changed]#Protected routes use `requires_auth` (`backend/app/middleware/auth_middleware.py`) to extract bearer tokens, verify JWTs via Supabase JWKS, and attach identity context to `g`.#

[source,python]
----
@wraps(f)
def wrapper(*args, **kwargs):
    token = extract_token()
    payload = verify_jwt(token)
    g.user_id = payload.get("sub")
    g.user = payload
    return f(*args, **kwargs)
----

[.changed]#This separates authentication concerns from business handlers and keeps route logic focused on domain operations.#

===== Scheduling Domain Service

[.changed]#Core slot computation is represented in `backend/app/services/scheduling.py` through typed domain structures (`TimeRange`, `DailyAvailability`) and `generate_available_slots(...)`.#

[source,python]
----
@dataclass(frozen=True)
class DailyAvailability:
    date: date
    working_hours: TimeRange
    blocked_periods: list[TimeRange]
    slot_minutes: int

[.changed]#This service is unit-tested in `backend/tests/unit/test_scheduling.py` and `backend/tests/unit/test_scheduling_properties.py`, so scheduling behavior can be validated independently from HTTP transport.#
