==== *Domain Requirements*


===== Appointment Identity and Association

*Domain basis:*  
An appointment is a concrete scheduling commitment, not a loose reminder.

*Requirements:*

* [[REQ-APPT-F-01]]REQ-APPT-F-01: [.changed]#The system must associate each appointment with exactly one patient, exactly one primary provider, exactly one clinic, exactly one consultation type, and exactly one time slot.#

* [[REQ-APPT-F-02]]REQ-APPT-F-02: [.changed]#The system must preserve appointment history, including status transitions, as part of longitudinal patient-provider coordination.#

===== Time Slot Semantics and Capacity

*Domain basis:*  
Provider time is the scarce resource in this domain and must be modeled explicitly.

*Requirements:*

* [[REQ-SLOT-F-01]]REQ-SLOT-F-01: [.changed]#The system must represent provider availability as discrete time slots with explicit slot status values `Available`, `Held`, `Reserved`, or `Expired`.#

* [[REQ-SLOT-F-02]]REQ-SLOT-F-02: [.changed]#The system must prevent more than one active appointment from reserving the same time slot at the same time.#

===== Consultation-Type and Duration

*Domain basis:*  
Consultations differ in expected scheduling footprint.

*Requirements:*

* [[REQ-CONSULT-F-01]]REQ-CONSULT-F-01: [.added]#The system must associate each consultation type with an expected duration used for slot allocation and conflict checking.#

* [[REQ-CONSULT-F-02]]REQ-CONSULT-F-02: [.added]#The system must treat expected duration as a planning parameter and must not assume exact real-world consultation runtime.#

===== Confirmation and Prerequisites

*Domain basis:*  
A request and a confirmation are different domain facts.

*Requirements:*

* [[REQ-CONFIRM-F-01]]REQ-CONFIRM-F-01: [.changed]#The system must record whether an appointment request requires referral, insurance authorization, or staff review before confirmation.#

* [[REQ-CONFIRM-F-02]]REQ-CONFIRM-F-02: [.changed]#The system must prevent an appointment from entering `Confirmed` until all required prerequisites have been satisfied.#

* [[REQ-CONFIRM-F-03]]REQ-CONFIRM-F-03: [.added]#The system must record whether required confirmation evidence has been received for appointments that depend on confirmation.#

===== Cancellation and Rescheduling

*Domain basis:*  
Cancellation and rescheduling are first-class scheduling operations, not ad hoc edits.

*Requirements:*

* [[REQ-BOOK-F-01]]REQ-BOOK-F-01: [.changed]#The system must support patient or caregiver requests for available appointment slots and must prevent double booking.#

* [[REQ-BOOK-F-02]]REQ-BOOK-F-02: [.changed]#The system must support cancellation of an eligible future appointment and must release the associated time slot when cancellation succeeds.#

* [[REQ-BOOK-F-03]]REQ-BOOK-F-03: [.added]#The system must support clinic-defined cancellation policy rules, including minimum advance notice windows when configured.#

* [[REQ-BOOK-F-04]]REQ-BOOK-F-04: [.added]#The system must support rescheduling by releasing the previous slot and associating the appointment with a replacement slot in one coherent domain transition.#

===== Waitlist Handling

*Domain basis:*  
Waitlist behavior must be explicit because it directly affects fairness and reassignment.

*Requirements:*

* [[REQ-WAIT-F-01]]REQ-WAIT-F-01: [.added]#The system must support patient waitlist enrollment when no acceptable slot is currently available.#

* [[REQ-WAIT-F-02]]REQ-WAIT-F-02: [.added]#The system must preserve explicit eligibility and ordering rules for selecting a waitlisted patient when a slot becomes available.#

===== Attendance Outcomes

*Domain basis:*  
Attendance outcomes feed planning, continuity, and follow-up workflows.

*Requirements:*

* [[REQ-ATTEND-F-01]]REQ-ATTEND-F-01: [.changed]#The system must record whether a confirmed appointment was completed, cancelled, or marked as `NoShow`.#

===== Provider Eligibility Scope

*Domain basis:*  
The platform may serve clinics with different provider mixes and policies.

*Requirements:*

* [[REQ-PROVIDER-F-01]]REQ-PROVIDER-F-01: [.added]#The system must support clinic-defined policy for which provider types are bookable through the platform rather than assuming every bookable provider is necessarily a physician.#
