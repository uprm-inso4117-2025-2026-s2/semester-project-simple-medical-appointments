==== *Appointment Scheduling UI Usability Review*
:author: Ariana Rodriguez

===== Overview

Identify strengths, possible usability concerns, and improvement opportunities within the scheduling workflow. Document how users interact with the interface while booking an appointment and whether the process is intuitive, efficient, and easy to understand.

===== Patient Experience Scheduling Workflow

The current scheduling process follows these steps:

. User selects an appointment type
. User selects an available date
. User selects an available time slot
. User reviews confirmation details
. User confirms or cancels the appointment

==== Usability Strengths

===== S1 - Clear Section Organization

The scheduling interface separates each scheduling step into distinct visual sections. Appointment selection, calendar selection, time slots, and confirmation details are easy to identify.

This helps reduce visual clutter, improve readability, and supports first-time.

===== S2 - Visible Selected States

Selected appointment types and selected dates are highlighted clearly using borders and color indicators.

This improves user confidence, makes selections easy to identify, and reduces accidental mistakes.

===== S3 - Time Slot Availability Feedback

Unavailable time slots are visually disabled while available slots remain selectable.

Helps prevent invalid selections, improve scheduling efficiency, and provides immediate visual feedback.

==== Usability Observations

===== U1 - Incomplete Confirmation Message

The confirmation section displays incomplete information before a user selects a time slot.

Example:

----
Book Normal appointment appointment September 5, 2025 at ?
----

Potential issues:

* May confuse users
* Makes the interface appear unfinished

===== U2 - Confirmation Button Appears Active Too Early

The Confirm button is visible before all required scheduling selections are completed.

Potencial issues:

* Users may attempt incomplete confirmations
* Creates unnecessary interactions
* Can interrupt workflow clarity

==== Recommendations

===== R1 - Improve Confirmation Message Logic

Update the confirmation section so incomplete information is not displayed before all required selections are made.

Recommended behavior:

* Display helper text until all selections are completed
* Replace the "?" placeholder with a helper message

Expected benefits:

* Improves workflow clarity
* Reduces confusion
* Improves user guidance

===== R2 - Disable Confirmation Until Completion

Disable the Confirm button until:

* Appointment type is selected
* Date is selected
* Time slot is selected

Expected benefits:

* Prevents incomplete submissions
* Improves workflow guidance
* Reduces user errors

==== Conclusion

The appointment scheduling interface provides a clean and organized workflow that supports usability and ease of navigation. The separation of scheduling steps and visible selection states help users understand the scheduling process efficiently.

Most usability concerns identified are minor and mainly related to confirmation feedback. These issues can be improved through future UI refinements.

=== Prototype-Based Usability Validation of the Patient Scheduling Interface
:author: Tasnim Said Khader

==== Introduction
Usability is considered the absence of frustration in using a product, where a user can perform what they want in the way they expect without hindrance. Usability Testing falls under validation, which uses external sources of reference to ensure that the internal design is valid and that it meets user's expectations. 

==== Task 1 - Appointment Scheduling
Scenario: patient 1 attempts to locate an available appointment and complete the booking process. 

[cols="1,3,3,3", options="header"]
|===
| Evaluation Type | Findings | Observed Points | Assessment

| *Learnability* 
a| Users can generally understand the booking flow because it follows a recognizable sequence: 

    Clinic/Doctor selection -> weekly schedule -> select time -> booking confirmation.

The weekly availability grid provides a visual indication of open slots (in green), which helps users quickly identify availability. 
a| - Users may initially hesitate when deciding where to click after selecting a clinic, because the transition from doctor selection to weekly availability is not visually emphasized.
- Some users may be unsure whether green blocks are clickable appointment slots or simply indicators of availability.
| A first-time user could likely complete the task, but some guidance or trial-and-error may be required. 

| *Efficiency*
a| Once users understand the interface, appointment selection becomes relatively fast due to: 

* weekly visual schedule
* clinic information visibility
* structured filtering options

However, efficiency may decrease because:

* the filter bar icons are small and minimally labeled.
* users must mentally interpret schedule availability rather than seeing explicitly "available" labels.
| 
| Users familiar with the interface would likely complete booking quickly, but first-time users may require extra navigation time. 

| *Error Evaluation*
a| *Potential Navigation Errors*

1. Filter Confusion: Users may not understand whether they must select: Location, Specialty, Doctor, Medical Plan, before continuing.
2. Appointment Slot Interpretation: Green time blocks do not explicitly indicate "Click to book"
3. Unavailable Slot Workflow: The unavailable slot screen provides a cancellation notification option, but it is unclear: what happens after clicking YES and whether the patient joins a waitlist.
|
| Most errors would stem from interface ambiguity rather than system complexity.
|===

==== Task 2 - Appointment Management/Rescheduling
Scenario: patient 2 attempts to review appointment details and reschedule. 

[cols="1,3,3,3", options="header"]
|===
| Evaluation Type | Findings | Observed Points | Assessment

| *Learnability* 
| The confirmation screen clearly communicates booking details, which improves confidence. However no obvious “Reschedule” option is visible in the mockups. Users may struggle to identify how to modify an existing appointment.
|
| Viewing appointment details is easy, but rescheduling workflow is unclear.

| *Satisfaction*
a| *Positive Aspects*

* Clean, organized layout
* Minimal clutter
* Large schedule visualization
*Appointment confirmation provides reassurance

*Negative Aspects*

* Interface feels visually dense in some areas.
* Low visual emphasis on important actions.
* Limited feedback on selected actions.
| 
| Users would likely feel capable of booking appointments, but some uncertainty may remain.

| *Accessibility*
| Some strengths we concluded include: large calendar and time-slot spacing, high contrast between available/unavailable areas, organized information hierarchy.
a| There have been some concerns regarding: 

1. Elderly users; where filter dropdowns may feel small, text size in appointment cards could be difficult to read and clickable areas are not visually obvious.
2. Visual Accessibility; where green-only availability indicators may create problems for colorblind users and lack of accessibility cues besides color (icons/text labels missing).
| Needs improvement for elderly & accessibility support.
|===

==== Usability Deficiency Report
1. Low Discoverability of Appointment Selection

- *Issue*: Available slots do not clearly signal interaction.
- *Reason*: Users may hesitate or miss booking actions.

2. Waitlist Workflow Is Unclear

- *Issue*: Unavailable slot screen does not explain what happens after opting for notification.
- *Reason*: Reduced user confidence.

3. Rescheduling Process Is Missing
- *Issue*: No visible pathway for appointment management.
- *Reason*: Users may struggle to modify bookings.

4. Accessibility Limitations
- *Issue*: Small text and color-only availability indicators.
- *Reason*: Elderly and visually impaired users may struggle.

==== Design Change Suggestions
1. Make Appointment Slots Clearly Clickable
- Add labels or hover indicators such as: “Available — Click to Book”.

2. Improve Waitlist Communication
- Replace current text with clearer messaging: “Join waitlist and receive notification if a slot becomes available.”

3. Add a Visible Reschedule Button
- Include: View Appointment → Reschedule → Choose New Slot.

4. Improve Accessibility
Add: Larger text option, bigger dropdown menus, icons + labels (not only color), accessibility mode for elderly users.

=== *Usability review for colorblind themes with UI*
:author: Sebastian Suarez

==== Overview

This review evaluates the usability of the colorblind themes implemented by the Patient Experience Team. The goal is to identify strengths, potential usability concerns, and opportunities for improvement in how the application supports users with color vision deficiencies. The review focuses on theme switching, color palette effectiveness, and the consistency of the colorblind experience across all pages.

==== Colorblind Theme Workflow

The current workflow for colorblind accessibility includes the following steps:

. User navigates to Account Settings
. User selects a colorblind theme (Normal, Protanopia, Deuteranopia, Tritanopia)
. The selected theme is applied immediately and persists across all pages and browser refreshes
. User continues to interact with the application using the chosen theme

==== Usability Strengths

===== S1 - Accessible Theme Switching

Theme selection is clearly presented in the Account Settings page, allowing users to easily toggle between normal and colorblind modes. The interface provides radio buttons for each theme, making the selection process straightforward.

===== S2 - Distinct Color Palettes

Each colorblind mode uses a carefully chosen palette that avoids problematic color combinations (e.g., red/green for protanopia). This helps ensure that key interface elements remain distinguishable for users with different types of color vision deficiencies.

===== S3 - Persistent and Consistent Experience

Once a colorblind theme is selected, it remains active across all pages and after browser refresh, providing a seamless and consistent experience for the user.

==== Usability Observations

===== U1 - Reliance on Color Alone for Status

Some status indicators (such as appointment status or calendar slots) rely solely on color to convey meaning. This may cause confusion or slow down navigation for users who cannot distinguish certain colors, especially in colorblind modes.

===== U2 - Feedback and Selection States

While most feedback and selection states are clear, there are instances where additional icons or text labels would help users who have difficulty perceiving color differences.

===== U3 - Theme Preview

Currently, users must select a theme to see its effect. Providing a preview of each colorblind theme before applying it could improve user confidence and satisfaction.

==== Recommendations

===== R1 - Supplement Color with Icons or Labels

Add icons or text labels to all status indicators (e.g., confirmed, pending, cancelled) so that meaning is not conveyed by color alone. This will improve clarity for all users, especially those with color vision deficiencies.

===== R2 - Enhance Visual Distinction of Interactive Elements

Review all interactive elements (buttons, toggles, slots) to ensure they are visually distinct in all colorblind themes, using both color and shape or border.

===== R3 - Provide Theme Previews

Allow users to preview each colorblind theme in the settings page before applying it, helping them make informed choices.

===== R4 - Continue User Testing

Conduct further usability testing with individuals who have color vision deficiencies to identify any remaining pain points and validate improvements.

===== R5 - Document Color Palette Choices

Maintain documentation of all color palette choices and the rationale behind them to support future accessibility reviews and updates.

==== Conclusion
The implementation of colorblind themes in the web application demonstrates a strong commitment to accessibility. The clear theme switching, distinct color palettes, and consistent experience are significant strengths. However, there are opportunities to enhance usability by supplementing color with additional indicators, providing theme previews, and ensuring all interactive elements are easily distinguishable. Ongoing user testing and documentation will be essential to maintaining and improving the accessibility of the application for all users.
