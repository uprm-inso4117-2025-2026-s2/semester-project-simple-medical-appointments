===== *Scenario-Based Stakeholder Validation*

**Scenario 1: Specialist Booking with Waitlist and Insurance Constraint**

**Actors:**  
- Patient: Ana Rivera.  
- Provider: Dr. Luis Santiago.  
- Staff: Administrative assistant Maria Torres.

**Context:**  
Ana needs a cardiology appointment. The clinic workflow requires referral and insurance authorization before confirmation.

**Walkthrough:**

1. Ana requests an appointment for cardiology.  
2. Staff identifies a candidate slot and records the request as `PendingApproval` because insurance authorization is not yet received.  
3. Ana asks to join waitlist for earlier openings; staff registers waitlist eligibility.  
4. Another patient cancels, creating a free slot.  
5. [.added]#The free slot is NOT auto-confirmed for Ana yet because authorization is still pending.#  
6. [.added]#Insurance authorization is then received and recorded.#  
7. [.changed]#Only after prerequisites are cleared, the system confirms Ana into the available slot and sends status notifications.#

**Why this resolves prior inconsistency:**  
[.changed]#The scenario now explicitly shows the intermediate event "authorization received" before any waitlist-driven confirmation. This directly justifies the refinement that waitlist auto-confirmation is conditional on cleared prerequisites.#
