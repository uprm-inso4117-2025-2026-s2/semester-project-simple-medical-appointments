=== *Other Activities than Just Developing Source Code*
Projects are successful when coding is supported by planning, communication, and documentation. These activities keep the team organized and ready for future development.

* Beyond writing source code, the project requires continuous documentation efforts to ensure that ideas, decisions, and structures remain clear and traceable. This includes writing user guides that explain how patients and clinic staff interact with the system, preparing technical explanations of architectural decisions, documenting database structures, and maintaining updated project reports for academic evaluation. Documentation is not treated as a final step, but as an ongoing process that evolves alongside development to preserve clarity and coherence across milestones.

* While the application is not yet developed enough for full-scale testing, it is still necessary to plan for quality assurance. This involves deciding how unit testing, integration testing, and usability evaluation will eventually be carried out once prototypes and code are available. In parallel, version control practices such as branching strategies, pull requests, and code reviews can already be defined so the team is prepared to manage collaboration effectively when development begins. These preparatory activities set the standard for a structured and reliable workflow.

* Version control management is necessary to coordinate a large team working simultaneously on different parts of the system. Maintaining a structured repository allows team members to work in parallel branches without overwriting each other’s contributions. Code reviews, commit tracking, and organized pull requests reduce conflicts and improve accountability. Regular backups and repository hygiene also protect the project from accidental loss or corruption.

* Effective coordination requires deliberate project management practices. Timelines must be defined early, milestones clearly structured, and deliverables aligned with course deadlines. Task assignments are distributed according to functional teams, but progress must be monitored collectively to avoid bottlenecks. Regular meetings create opportunities to clarify misunderstandings, adjust priorities, and ensure that conceptual decisions remain aligned with the overall domain vision.

* Clear and structured communication supports collaboration across functional teams. Decisions taken in meetings must be recorded, responsibilities explicitly assigned, and updates shared consistently. Because different teams focus on distinct aspects of the domain—such as scheduling, patient experience, or documentation—misalignment can easily occur without deliberate communication channels. Maintaining transparency reduces duplication of work and prevents conceptual inconsistencies.

* Many of these supporting activities occur in parallel with development rather than sequentially. Documentation is written while features are implemented, testing begins as soon as a component becomes stable, and presentation materials are prepared before final deployment. This parallel execution improves efficiency and prevents last-minute overload before milestone deadlines. It also encourages iterative refinement instead of postponing evaluation.
