== Introduction
This Lecture Topic Task expands the user ER diagram to align it with the
`auth.users` structure of Supabase.
It applies test planning principles to support risk analysis, test case
design, and system modeling.


== Test Planning Context
The test planning lesson highlights the importance of understanding the
system structure to prioritize tests effectively.

[quote, "Lecture 2: Test Planning [1]", "Key Principles"]
____
* "Cannot test every possible situation."
* "Must invest your resources wisely."
* "Deliver the right tests, in the right order."
* "Code structure," "Functionality," "Input space."
____

These principles justify the need for a complete ER diagram before designing
test cases.

== Expansion of the User Management ER Diagram

=== Objective
Extend and refactor the previously completed ER diagram to match the
Supabase database user management module.


[quote, "Supabase Documentation [2]", "Auth Concepts Users"]
____
A user in Supabase Auth is someone with a user ID, stored in the Auth
schema.
Once someone is a user, they can be issued an Access Token, which can be
used to access Supabase endpoints.
The token is tied to the user, so you can restrict access to resources via
RLS policies.
____

=== Proposed Solution
Create a complete and shareable ER diagram that:

* Defines the entities:
** `auth.users` (Supabase references)
** `roles`
** `permissions`
** `profiles`
** `settings`
* Establishes all relationships between them.

=== Success Criteria
* Shareable ER diagram created with appropriate entities and their
  relationships.
* Diagram supports test planning and risk analysis.
