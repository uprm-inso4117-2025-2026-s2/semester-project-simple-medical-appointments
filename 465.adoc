==== Property-Based Testing Framework Evaluation Report
:author: Keishlyany Sanabria (@keisanabria)

===== Overview

This document presents a comparative evaluation of property-based testing frameworks suitable for the medical application stack (React Native frontend and Node.js backend).

The goal is to recommend a framework based on:

* Generator expressiveness
* Shrinking quality
* Classification and statistics support
* Integration and learning curve

===== Candidate Frameworks

The following frameworks were selected based on relevance to the project’s technology stack:

* *fast-check* (TypeScript / JavaScript)
* *Hypothesis* (Python)
* *FsCheck* (.NET / C# / F#)

===== Evaluation Criteria

====== Generator Capabilities

Property-based testing relies on generators to explore the input space. As discussed in the lecture, generators must:

* Produce structured and constrained data
* Support composition (for example: lists, pairs, trees)
* Allow custom generators (for example: arb_tree example from slides 22-24)

====== Shrinking Quality

Shrinkers minimize failing test cases to simpler counterexamples. Effective shrinking helps developers quickly identify root causes (slides 37-40).

====== Classification & Statistics

Classification ensures that generated values adequately cover the input space. This aligns with the principle:

> “Ensure the value space is adequately sampled”

====== Integration & Learning Curve

Ease of integration with existing tools (for example: Jest, Mocha) and community support are critical for adoption.

===== Conceptual Shrinking Example

Consider a failing property:

----
Reverse three times should equal original list
----

A generator produces:

----
[2387656796, -1933289941, 2127570389]
----

With shrinking:

* fast-check → `[1, 0]`
* Hypothesis → `[0]` (often minimal)
* FsCheck → `[0, 1]`

This demonstrates how shrinking reduces debugging complexity by minimizing counterexamples.

===== Recommendation

*fast-check* is recommended as the primary property-based testing framework for the app.

====== Justification

1. *Technology Alignment*

The application uses React Native and Node.js, making fast-check the most natural fit due to its native JavaScript/TypeScript support.

2. *Generator Expressiveness*

fast-check supports composable generators similar to those described in the lecture (for example: lists, pairs, and custom structures), enabling complex domain modeling.

3. *Adequate Sampling of Value Space*

fast-check provides classification and statistics tools that help ensure:

> the value space is adequately sampled

This is critical for testing medical workflows where edge cases (for example: appointment times, patient data) must be thoroughly explored.

4. *Integration Ease*

fast-check integrates seamlessly with Jest, which is commonly used in React Native projects, minimizing adoption overhead.

5. *Shrinking Effectiveness*

While Hypothesis has slightly stronger shrinking, fast-check provides sufficiently effective shrinking for JavaScript environments without requiring additional infrastructure.

====== Final Decision

Adopt *fast-check* for both frontend and backend testing.
